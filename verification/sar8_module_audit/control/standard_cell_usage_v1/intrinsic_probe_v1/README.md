**尚未核定当前 TMI 器件的可分离 D–S 导电输出，因此不生成含义未明的测量候选。** 没有改库、加保存项、运行仿真或继续扫 CP 串阻。普通 `bsimbulk` 的 `ids`、`id` 不能未经核对便套到当前 TMI 器件。

## 已确认的映射与定义

| 证据 | 实际读到的内容 |
| --- | --- |
| 原生 SPI 精确实例 | DFCNQD1 的 MM65 使用 `nch_mac`，D/G/S/B＝`net176/mq/net184/VSS`；同堆叠 MM64、MM66 映射也一致。 |
| 当前 PDK | 冻结 SHA 核对通过；`cln28ull_1d8_elk_v1d8_3.scs` 第 14236 行有 inline `nch_mac(n1,n2,n3,n4)`，对应块至第 24525 行，块 SHA 已保留。未核定其中主 primitive 的别名路径，不编造 `.M1`。 |
| 原直连基线的实际 native 日志 | 58 个器件报告为 `tmibsimbulk`；加载精确 `libTMImodel.so`，TMI 版本 `V102031.180001`。这是实际运行类型证据，与普通帮助主题有区别。 |
| 当前 Spectre | `21.1.0.509.isr12`；安装的 `bsimbulk` 帮助把 `ids` 作为 D–S 电流，把 `id` 作为总电阻性漏极电流；另列 `igidl/igisl/igs/igd/igb/ibs/ibd` 等分量。不能把 `id` 称作纯沟道电流。 |
| TMI 专属帮助 | `-h tmibsimbulk` 返回“无此主题”，尽管退出码为 0；`-h tmi_spec` 只给出接口版本 `v2021d01`，未给字段或符号映射。 |

这里未证明 `ids` 在当前 TMI 封装中保持同样的定义、方向和缩放，也未证明它可由原实例路径保存。尤其 MM65 保持阶段的 D 低于 S，必须核对**反向 VDS 时的电流符号／D–S 交换约定**。目前总端流仍只能支持“持续端口交换、恢复缓慢”，不能唯一归因为持续沟道电流或某一种寄生分量。

## 具体下一选择

最小下一项是由主会话提交**原直连基线的单实例原生信息／单点 OP 字段映射验证**，只针对 MM65，获取实际展开的 primitive／主实例别名及可用 `ids/id`、栅体电流字段；先验证名称、单位和端口，完整原功能／应力台不动。该验证只确认暴露字段，不能替代字段物理定义。

同时需要当前 `libTMImodel.so` 版本的 OP 说明明确三点：`ids` 是否排除了栅／体／结泄漏及位移电流；VDS<0 时的方向约定；inline 主实例与 nf／multi 的输出缩放。取得说明并完成这一次映射核对后，才准备原 5 ns 前沿及 5.5／5.95 ns 的分量轨迹测量。若得不到明确说明，保留归因限制，转向公开引脚／端压及功能可核验的诊断，不凭总端流改库。本次未生成上述信息验证 deck 或 managed recipe。
