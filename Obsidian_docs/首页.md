# SAR ADC 设计笔记

这里放我们共同整理、自己愿意回头读的笔记：为什么这样设计，实际看到了什么，哪里判断错了，后来如何纠正。

工程报告仍保留在仓库的 `docs/`。这里不复制每次运行日志、脚本操作和完整文件清单，也不把一次实验通过写成模块已经完成。

## 从这里读

- [[当前设计]]：现在采用什么电路，哪些结论成立，还有什么没解决。
- [[设计流程复盘]]：从 10-bit 探索到 8-bit 合龙，保留弯路和纠偏。

## 两套文档怎么分工

`docs/` 回答“证据在哪里、当时具体怎么测的”。`Obsidian_docs/` 回答“我们为什么这样做、现在怎样理解这件事”。实验记录不搬走，笔记也不靠复制一份报告来更新。

涉及数值的笔记要交代版本和条件。历史结果、当前基线、进行中的候选分开写；改正理解时保留原因，不把失败的历史抹掉。来源栏中的 `docs/...`、`config/...` 是相对于 ADC 仓库根目录的路径，位于这个笔记库之外，不是库内双链；需要细查时让 Codex 按路径读取。

## 我们怎么一起写

你可以直接改笔记、补充自己的理解，或留下“这里我还不明白”的问题，再告诉 Codex 笔记名和要整理的范围。我们轮流编辑同一篇，避免同时输入覆盖内容。Codex 需要重新读取文件，不会自动知道你选中了哪一段。

先把这几篇维护好，等某个模块值得单独讲时再拆新笔记，不预先铺满空目录和模板。
